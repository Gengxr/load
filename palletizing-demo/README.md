# 单盘动态码放规划 · 演示系统

基于多构型货运无人机的智能物资储运模拟验证平台 · 码盘与装载方案规划模块。

这是**「单盘动态码放规划」**的 Web Demo：给定一个货盘和分到这个货盘上的一批货物，
决定**每一件放在哪里**、**按什么顺序一件一件放上去**，并保证不仅最终状态、而且**每放一件之后的中间状态**都平衡、稳定。
全程三维动态演示，自动报告技术要求表 2-2 的各项指标。

> 多盘分配不在本 Demo 范围内，只预留了 JSON 输入接口（见[数据接口](#数据接口)）。

---

## 快速开始

**直接演示（推荐）**：双击 `../单盘动态码放演示.html`（单文件、离线可用，约 0.9 MB）。
建议用 Chrome / Edge 打开，1920×1080 全屏（F11）效果最好。

**开发运行**：

```bash
npm install
npm run dev          # http://localhost:5173
npm test             # 单元测试（27 项）
npm run bench        # 批量算法评测：各种货物场景 × 多个随机种子
npm run build:single # 重新打包单文件 HTML → dist-single/index.html
```

技术栈：Vue 3 + TypeScript + Three.js；算法运行在 Web Worker 中，纯 TS、不依赖 DOM，后续可平移到 Python 后端。

## 算法说明

### 1. 空间布局：每件放哪（`src/algo/layout.ts`）

1. **高度类**：按高度把货物分组（容差 5 mm），同层平整；矮件可叠成 2–3 件的"列"补齐层高。
2. **候选层**
   - 同规格：断头台动态规划（标准组合点）+ 五块风车式结构（`pattern.ts`）。**技术要求图 2-1 的 14 种单规格排布全部达到图中件数**，含中心留空的风车式；
   - 混合规格：MaxRects 装填（全局最优匹配，BSSF / BL / 接触点三种评分择优，`maxrects.ts`）。
3. **层变换**：镜像、转置（旋转 90°），按"支撑率 → 压缝 → 配平"选择方向，剔除支撑不足的件。
4. **层序列束搜索**：以"体积密度高、重件在前"为序选择层，垛高 ≤ 1200 mm，上层外轮廓外扩 ≤ 5%。
5. **收顶**：剩余货物用高度图自由码放（`freepack.ts`，10 mm 栅格 + 精确几何复核支撑）。
6. **兜底策略**：完全随机尺寸时同时跑"全自由码放"，两者择优。
7. **后处理**：相邻层按密度冒泡交换（重层在下，交换后全部约束复核）；层镜像 / 平移把重心拉回中心；同规格不同重量的货物重新指派（重件在下、左右配平）。

### 2. 动态顺序：先放哪件（`src/algo/sequence.ts`，核心）

- **先后约束图（DAG）**：货物从上方竖直放下，因此下方投影重叠的货物必须先就位。这同时保证了**每一个中间状态里，每件货物都被完整托住**（`precedence.ts`）。
- **目标**：在所有合法顺序中最小化

  ```
  J = w峰·max_k e_k + w均·mean_k e_k + w孔·封闭孔位数 + w行·平均行走距离 + w换·换层次数
  e_k = 放完第 k 件后，货物+货盘系统重心的水平偏心率 max(|Δx|,|Δy|) / 基准长度
  ```

- **束搜索**：每步保留最好的 B 个部分方案（默认 96），增量重心 O(1) 评估，Zobrist 哈希去重。
- **封闭孔位前瞻**：放下某件时若会把相邻空位四面围死，立即计入代价，避免工人"塞箱子"。
- **跨层码放**：允许超前最低未完成层 0/1/2 层（默认 1），但每次换层有代价，避免工人频繁换层。
- **对照基线**：传统"逐层、由远及近、从左到右"的行扫描顺序。

### 3. 指标评估（`src/algo/evaluate.ts`）

生产与报告共用一个评估器，测试中另有独立手算用例核对。

| 技术要求（表 2-2） | 本 Demo 口径 |
|---|---|
| 1 重心高度 ≤ (1/2+10%) 总高 | 总高 = 垛高 + 货盘 75 mm，含货盘自重（重心按几何中心） |
| 2 重心偏离几何中心 ≤ ±10% | 基准默认货盘 1219 mm，可切换为垛形 1000 mm |
| 3 货盘利用率 ≥ 80% | 按图 2-1 口径：相对 1000×1000，逐层（按支撑层级）计算，最顶一层不计 |
| 4 垛形外边界 ≤ 1000×1000×(1000–1200) | 垛高下限为软约束（货量由多盘分配决定） |
| 5 码盘垛形误差 ≤ 5% | 相邻层外轮廓每侧外扩 / 下层边长 |
| 7 方案生成 ≤ 120 s / 垛 | 实测见下表 |
| 研发约束 | 单件底面支撑率 ≥ 80% 且重心投影落在支撑区内；碰撞 / 越界 = 0 |

## 评测结果

`npm run bench -- 20`（每类 20 个随机种子，M4 芯片，单线程）：

| 场景 | 平均件数 | 全部放入 | 硬约束（支撑 / 碰撞 / 重心） | 利用率达标 | 生成用时（均 / 最大） | 过程峰值偏心 本方案 vs 传统 |
|---|---|---|---|---|---|---|
| 标准规格（5 种） | 94 | 19/20 | 20/20 | 19/20 | 0.71 s / 1.6 s | **2.7%** vs 11.1% |
| 多规格混装（8+ 种） | 111 | 20/20 | 20/20 | 17/20 | 0.90 s / 1.6 s | **2.8%** vs 11.0% |
| 图 2-1 单规格 | 138 | 20/20 | 20/20 | 20/20 | 0.58 s / 1.7 s | **2.4%** vs 11.5% |
| 随机尺寸（50 mm 档，压力测试） | 55 | 19/20 | 20/20 | 3/20 | 1.48 s / 3.2 s | **3.4%** vs 10.9% |

- 所有场景的码放顺序都满足先后约束（顺序非法 0 例），每一步放下的货物支撑率均 ≥ 80%。
- 随机尺寸下货物无法凑成平整层，利用率受货物本身限制，如实报告为"未达标"；稳定性与重心不受影响。
- 放不下的货物不会被硬塞，列入"未放入 · 人工处理"清单（保留人工参与接口）。

## 数据接口

**输入**（左侧"导入货物集合 JSON"）：多盘分配结果或仓储出库清单。

```json
{
  "schemaVersion": "0.1",
  "pallets": [
    { "palletNo": 1,
      "cargos": [
        { "id": "C0001", "rfid": "E2000017221101441890", "sku": "S01",
          "length": 400, "width": 300, "height": 200, "weight": 8.5 }
      ] }
  ]
}
```

也接受 `{ "cargos": [...] }` 或裸数组；字段可简写为 `l / w / h`；缺 `sku` 时按尺寸自动归类。多个货盘时可在界面上选择其中一盘。

**输出**（指标面板「分层方案」右上角的导出按钮）：每件的码放序号、层号、位置（垛形局部坐标，最小角点，mm）、尺寸、朝向、支撑件，
`pickSequence` 即散货出库顺序，另含 `remainingCargo`、各层信息、全部指标和过程平衡性摘要。字段与《系统架构与技术方案 v0.3》§4.2 的 `PalletizingPlan` 对齐。

```

├─ algo/                 纯算法（无 DOM，可直接移植）
│  ├─ types.ts           领域模型

│  ├─ maxrects.ts        混合规格单层装填
│  ├─ freepack.ts        高度图自由码放

│  ├─ precedence.ts      先后约束图
│  ├─ sequence.ts        平衡优先顺序束搜索 + 基线 + 逐步状态

│  ├─ planner.ts         主流程
│  └─ io.ts              JSON 导入导出

├─ components/           Vue 界面（三种视图 + 算法原理）

tests/                   单元测试（图 2-1 复现、评估器手算、硬约束、接口）
scripts/bench.ts         批量评测
```
