# 码盘与装载方案规划系统 · 演示版 V0.2

基于多构型货运无人机的智能物资储运模拟验证平台 ——「码盘与装载方案规划模块」的 Web 演示系统。

从一张**出库清单**出发，系统自动回答三个问题，并全程三维可视：

1. **多盘分配**：这些货物分成几盘、每盘放哪些；
2. **单盘码放**：每一盘上每件货放在哪、按什么顺序放（大件重件在下，全过程重心受控）；
3. **舱内装载**：码好的整托放进货舱的哪个货位，装载 / 投放 / 卸载每一步的重心是否在包络内。

同一张出库清单生成的码盘方案和舱内装载方案同时满足两边的约束。

---

## 快速开始

**直接演示（推荐）**：双击上一级目录里的 `码盘与装载方案规划系统.html`（单文件、离线可用，约 1.2 MB）。登录页已预填体验账号，直接点"登录"。

**开发运行**（Node 20+）：

```bash
npm install
npm run dev          # 开发服务，默认 http://localhost:5173
npm test             # 47 项算法测试
npm run build:single # 打包成单个 HTML → dist-single/index.html
npm run api          # RESTful 接口服务，默认 http://localhost:8787/api/v1/health
npm run bench        # 单盘算法批量评测
npx tsx scripts/alloc.ts 8 6   # 多盘分配评测（8 个种子 × 6 盘）
npx tsx scripts/cabin.ts 20    # 舱内装载评测（4 种构型）
```

## 算法说明

三个问题都是带约束的组合优化问题，采用可解释、可控时限的经典方法，不依赖黑箱模型。

### 1. 多盘分配（`src/algo/allocate.ts`、`pipeline.ts`）

- **层单元分解**：每种规格按单层最优图案的件数凑成"整层"；凑不满的零头按高度归档，同高的用 MaxRects 拼成"混合层"（利用率 ≥ 80% 才成层）；每个高度档最后剩下的零头打成一个"零头层"，留作某盘的顶层。
- **多路划分 + 局部搜索**：把层单元分给各盘——高度不超过垛高上限，各盘高度、重量尽量均衡，同规格尽量集中。先贪心构造，再用"移动一个单元 / 交换两个单元"下降。
- **验证回流**：每盘交给单盘算法真实求解（浏览器里是 Web Worker 并行池）。放不下的件回流到实际垛高最低、还有余量的货盘；仍放不下就加开一盘重新分配。

### 2. 单盘码放（`layout.ts`、`sequence.ts`、`evaluate.ts`）

- **布局**：同规格用"断头台切割动态规划 + 五块风车式"求单层最优图案（复现技术要求图 2-1 的 14/14 种件数）；混合规格用 MaxRects；层间通过镜像 / 转置压缝；束搜索选择层的组合与上下次序；顶部散件用高度图自由堆放。
- **大件、重件置底**：相邻层按"单位高度质量（重）+ 平均单件体积（大）"的优先级冒泡下沉，每次交换都重新校验支撑、5% 外扩和干涉，不满足就撤销。可在"参数"中分别开关。
- **顺序**：先建立先后约束图（下层先于上层、支撑件先于被支撑件），再用束搜索找顺序，代价是过程重心偏移的峰值与均值、行走距离、换层次数和封闭空洞。
- **评估**：独立的评估器按表 2-2 逐项核验利用率、重心、垛形、外扩、支撑、碰撞。

### 3. 舱内装载（`cabin.ts`）

- **三种重心**：货物合成重心（验收量，≤ ±10%）、各舱货物重心、含空机的整机重心（过程包络校验）。
- **求解**：货位数不多时全枚举（结果可证明最优）；规模大时模拟退火 + 两两交换。目标是装载后货物重心偏差最小、全过程整机重心不出包络、同等条件下过程峰值更小。
- **过程重心**：准静态分析，沿"舱门 ↔ 货位"的路径逐端点校核；进舱 / 离机瞬间质量突变，前后状态都查。装载离门远的先进，投放离门近的先出；多列、多舱时自动选择使偏差最小的先后顺序。
- **内置构型**（参数化示例，正式数据从舱段子系统获取）：中型单舱单列 6 位、大型单舱双列 8 位、串列双舱前 3 + 后 4、重载单舱双列 12 位。

## 评测结果

Apple M 系列笔记本、单线程 Node 下的批量评测（浏览器里各盘并行，联动用时约为表中的 1/3）。

**多盘分配 + 逐盘码放**（`scripts/alloc.ts 8 6`，每组 8 张出库单、每张约 6 盘）

| 出库单 | 平均件数 | 货盘全部指标达标 | 未放入 | 垛高极差 | 重量极差 | 联动用时（单线程） |
|---|---|---|---|---|---|---|
| 标准规格 6 种 | 575 | 47 / 48 | 0 | 175 mm | 38 kg | 3.7 s |
| 标准规格 10 种 | 701 | 48 / 48 | 0 | 150 mm | 38 kg | 5.7 s |
| 多规格混装 12 种 | 687 | 47 / 48 | 0 | 175 mm | 27 kg | 5.7 s |

**单盘码放**（`npm run bench`，每组 20 例）

| 场景 | 平均件数 | 全部放入 | 平均 / 最大用时 | 过程峰值偏心：本方案 vs 传统逐层 |
|---|---|---|---|---|
| 标准规格（5 种） | 94 | 19/20 | 0.80 s / 1.9 s | **3.6%** vs 11.2% |
| 多规格混装（8+ 种） | 111 | 20/20 | 1.01 s / 1.9 s | **3.3%** vs 11.4% |
| 图 2-1 单规格 | 138 | 20/20 | 0.57 s / 1.6 s | **2.4%** vs 11.5% |
| 随机尺寸（压力测试） | 55 | 18/20 | 1.50 s / 3.3 s | **3.3%** vs 10.9% |

**舱内装载**（`scripts/cabin.ts 20`，每组 20 例，整托 190–340 kg）

| 构型 | 整托 / 货位 | 求解方式 | 货物重心误差：本方案 vs 按顺序装入 | 全过程在包络内 | 平均用时 |
|---|---|---|---|---|---|
| 中型 M6 | 6 / 6 | 全枚举 720 种 | **0.03%** vs 1.51% | 20/20 | 0.8 ms |
| 中型 M6 | 4 / 6 | 全枚举 360 种 | **0.08%** vs 15.20% | 20/20（对照 0/20） | 0.2 ms |
| 大型 L8 | 8 / 8 | 全枚举 40,320 种 | **0.02%** vs 2.01% | 20/20 | 20 ms |
| 串列双舱 T7 | 5 / 7 | 全枚举 2,520 种 | **0.04%** vs 14.17% | 20/20（对照 0/20） | 0.7 ms |
| 重载 H12 | 12 / 12 | 模拟退火 | **0.01%** vs 1.52% | 20/20 | 29 ms |

装载规划耗时均在几十毫秒以内，远快于"4 货盘/秒"的要求。

## 数据接口

界面里的"数据中心 → 接口管理"可以查看每个接口基于当前数据的完整报文，并复制、下载。`npm run api` 提供同一套算法的 HTTP 服务：

| 方法与路径 | 作用 |
|---|---|
| `GET /api/v1/health` | 服务状态 |
| `GET /api/v1/cabin/configs` | 内置舱段构型 |
| `POST /api/v1/palletizing/plans` | 出库清单 → 多盘分配 + 各盘码放方案 + 散货出库顺序 |
| `POST /api/v1/loading/plans` | 整托货物 + 构型 → 货位、朝向、装载 / 投放顺序、过程重心 |
| `POST /api/v1/joint/plans` | 出库清单 + 构型 → 码盘方案与装载方案（联动） |

出库清单示例（字段 `length/width/height` 单位 mm，`weight` 单位 kg）：

```json
{
  "orderId": "CK20261006-001",
  "configId": "M6",
  "cargos": [
    { "id": "C0001", "rfid": "E2000017221101441890", "sku": "S01",
      "length": 400, "width": 300, "height": 200, "weight": 8.5 }
  ]
}
```

整托数据示例（重心 x/y 为相对货盘几何中心的偏移，z 为距货盘底面的高度）：

```json
{ "configId": "L8",
  "pallets": [ { "palletId": "P01", "grossWeight": 300.5, "cog": { "x": 4, "y": -6, "z": 520 }, "size": [1219, 1219, 1150] } ] }
```

对外接口的路径与字段是我方初稿，正式协议需与两家子系统供应商共同确认。

## 代码结构

```
src/
  algo/            纯 TypeScript 算法（不依赖界面，可在 Node 中运行）
    allocate.ts      多盘分配
    pipeline.ts      分配 → 逐盘码放 → 回流的联动流程
    layout.ts        单盘空间布局（pattern.ts / maxrects.ts / freepack.ts 为其子模块）
    sequence.ts      码放顺序（precedence.ts 为先后约束图）
    evaluate.ts      码盘指标评估
    cabin.ts         舱内装载：构型、求解、过程重心
    generator.ts     模拟货物生成
    io.ts            导入导出与接口报文
  viz/             Three.js 三维场景：PalletViewer（单盘）、FleetViewer（多盘总览）、CabinViewer（货舱）
  views/           四个工作区与登录页
  components/      面板、时间轴、图表等
  store.ts         全局状态与规划流程
  taskPool.ts      Web Worker 并行任务池
  persist.ts       本地持久化
scripts/           评测脚本与接口服务
tests/             算法测试（vitest）
```

## 口径、假设与已知限制

- **利用率**按技术要求图 2-1 的口径：相对 1000×1000 垛形面积、逐层计算、顶层不计。按整个 1219×1219 货盘面积计算在几何上达不到 80%，需甲方确认。
- **重心偏移基准**默认取货盘边长 1219，可切换为垛形 1000。
- **支撑率下限 80%**、层间压缝率、过程包络等为研发假设，待确认。
- **舱段构型、空机质量属性、理论重心、包络**均为内置示例值，由配置驱动；正式数据以舱段子系统提供的为准。
- 过程重心是准静态分析，不是飞行动力学仿真。
- 演示版的登录在本机校验，数据保存在浏览器本地；正式版对应服务端的认证、数据库与真实接口收发。
- 货物重心假设在几何中心；实测重心通过"实测复核"流程回传后参与装载复核。
