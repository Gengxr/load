# 码盘与装载方案规划系统 · 演示版 V0.3

无人货运空投智能仓储物流体系 ——「码盘与装载方案规划模块」的 Web 演示系统。

干线集中转运效率高，支线分发到一线的环节慢，物资容易延误甚至失效。用低空无人机空投来解决支线分发，
前提是把散件物资又快又稳地码到货盘上、装进飞机。本系统演示的就是这一段的规划算法。

**输入**：出库清单——每件货物的尺寸、重量和属性（包装类型：纸箱 / 木箱 / 军用特种箱；承压上限；是否怕压）。货物均为规则直方体。
**单码盘可用空间**：1.2 m × 1.2 m × 1.5 m。

**输出**：从一张出库清单出发，系统自动回答三个问题，并全程三维可视：

1. **多盘分配**：这些货物分成几盘、每盘放哪些；
2. **单盘码放**：每一盘上每件货放在哪、按什么顺序放；
3. **舱内装载**：码好的整托放进货舱的哪个货位，装载 / 投放 / 卸载每一步是否都在飞机重心包线内。

码放方案同时兼顾四件事：**空间利用率、码放平衡性、货物承压合理性、飞机重心包线约束**。

同一份方案有**两种落地方式**，不需要为执行设备另做适配：

- **人工引导**：工位大屏逐件提示位置、朝向和顺序，工人放好后踩脚踏确认；
- **机械臂**：方案展开成逐件的取放指令（货盘坐标系下的位姿、转角、安全高度、抓取方式），码垛机械臂直接执行。

## 快速开始

**直接演示（推荐）**：双击上一级目录里的 `码盘与装载方案规划系统.html`（单文件、离线可用，约 1.3 MB）。登录页已预填体验账号，直接点"登录"。

**开发运行**（Node 20+）：

```bash
npm install
npm run dev          # 开发服务，默认 http://localhost:5173
npm test             # 56 项算法测试
npm run build:single # 打包成单个 HTML → dist-single/index.html
npm run api          # RESTful 接口服务，默认 http://localhost:8787/api/v1/health
npm run bench        # 单盘算法批量评测
npx tsx scripts/presets.ts standard 1 2 3   # 端到端评测：分盘 → 码放 → 装载（预设名 + 若干种子）
npx tsx scripts/dblf.ts 20     # 单盘：本方案 / 逐层行扫描 / 经典算法 DBLF 三方对比
npx tsx scripts/cabin.ts 20    # 舱内装载评测（4 种构型）
```

## 算法说明

三个问题都是带约束的组合优化问题，采用可解释、可控时限的经典方法，不依赖黑箱模型。

### 1. 多盘分配（`src/algo/allocate.ts`、`pipeline.ts`）

- **层单元分解**：每种规格按单层最优图案的件数凑成"整层"；凑不满的零头按高度归档，同高的用 MaxRects 拼成"混合层"（利用率 ≥ 80% 才成层）；每个高度档最后剩下的零头打成一个"零头层"，留作某盘的顶层。
- **多路划分 + 局部搜索**：把层单元分给各盘——高度不超过垛高上限，各盘高度、重量尽量均衡，同规格尽量集中。先贪心构造，再用"移动一个单元 / 交换两个单元"下降。
- **验证回流**：每盘交给单盘算法真实求解（浏览器里是 Web Worker 并行池）。放不下的件回流到实际垛高最低、还有余量的货盘；仍放不下就加开一盘重新分配。

### 2. 单盘码放（`layout.ts`、`bearing.ts`、`sequence.ts`、`evaluate.ts`）

- **布局**：同规格用"断头台切割动态规划 + 五块风车式"求单层最优图案（复现技术要求图 2-1 的 14/14 种件数）；混合规格用 MaxRects；层间通过镜像 / 转置压缝；束搜索选择层的组合与上下次序；顶部散件用高度图自由堆放。
- **大件、重件置底**：相邻层按"单位高度质量（重）+ 平均单件体积（大）"的优先级冒泡下沉，每次交换都重新校验支撑、5% 外扩和干涉，不满足就撤销。可在"参数"中分别开关。
- **货物承压**：每件货物带一个承压上限（顶面最多能压多重）。压重的算法是：一件货物把"自重 + 顶上的压重"按接触面积比例传给正下方托住它的各件，从上往下逐件累加。保证不超限分三步——
  ① 选层时预估"把剩下的货全压上去"会不会压坏已放的层，优先让耐压的层在下；② 排好后若仍有超限，把不耐压的层往上换；
  ③ 还压不住，就把压在它上面的最顶上一件卸下，列入"未放入"，由多盘流程转到别的货盘。所以给出的方案里不会有被压超限的货物。
- **顺序**：先建立先后约束图（下层先于上层、支撑件先于被支撑件），再用束搜索找顺序，代价是过程重心偏移的峰值与均值、行走距离、换层次数和封闭空洞。
- **起步阶段**：货盘上的货物还不到整盘重量的 20% 时，放下一件较重的货物就会让重心明显偏移（货物比货盘重得多，物理上无法避免），而此时偏载力矩很小。
  这几步不计入"过程峰值偏心"和"超限步数"，但曲线照常画出，三维里的容差区显示为琥珀色。
- **评估**：独立的评估器按表 2-2 逐项核验利用率、重心、垛形、外扩、支撑、碰撞，并核验货物承压。

### 3. 对照对象（`sequence.ts` 的逐层行扫描、`dblf.ts`）

码放顺序和过程重心目前没有查到公认的行业标准或公开基准，所以用两个对照对象：

- **逐层行扫描**：与本方案同一个垛形，只把顺序换成"一层码满再码下一层，每层由远到近、从左到右"。这是自定义的对照基线，反映常见人工习惯，**不是某项标准**。
- **DBLF**（Deepest-Bottom-Left with Fill，最深-最低-最左填充；Karabulut K., İnceoğlu M. M., ADVIS 2004, LNCS 3261: 441–450）：三维装箱文献中常用的对照算法，位置和顺序都由它生成。
  用于货盘时的约定："深"取远离操作者一侧；货物按体积从大到小放（原文用遗传算法搜索次序）；不允许侧放；与本方案受同样的货盘空间和支撑率约束；它不考虑货物承压。
  DBLF 是为集装箱设计的，下面的对比说明码盘需要专门处理重心、分层、承压和顺序，不是对 DBLF 本身的否定。

### 4. 机械臂作业指令（`robot.ts`）

把码放方案按顺序展开成逐件的"取 — 放"任务，与具体设备无关：

- 位姿用工具中心点（吸盘 / 夹具下表面中心）表示：取料位姿在**取料坐标系**（输送线末端定位挡块处），放置位姿在**货盘坐标系**（可用区域左前角、货盘上表面）；
- 每件给出放置位置 X/Y/Z、绕竖轴转角、平移安全高度（高出已码货物 120 mm 以上）、进入高度、抓取方式（纸箱吸盘、木箱与特种箱夹抱）、速度档（重件和怕压件降速）、必须先就位的支撑件；
- 另给出执行这份任务所需的工作空间和最大负载，用来核对机械臂选型；
- 现场只需标定两个坐标系，机械臂控制器按顺序执行即可，不需要再做装箱计算或路径规划。界面里的四轴机械臂只是把这份指令演示出来。

### 5. 舱内装载（`cabin.ts`）

- **三种重心**：货物合成重心（验收量，≤ ±10%）、各舱货物重心、含空机的整机重心（过程包络校验）。
- **求解**：货位数不多时全枚举（结果可证明最优）；规模大时模拟退火 + 两两交换。目标是装载后货物重心偏差最小、全过程整机重心不出包络、同等条件下过程峰值更小。
- **过程重心**：准静态分析，沿"舱门 ↔ 货位"的路径逐端点校核；进舱 / 离机瞬间质量突变，前后状态都查。装载离门远的先进，投放离门近的先出；多列、多舱时自动选择使偏差最小的先后顺序。
- **内置构型**（无人运输机货舱的参数化示例，正式数据从舱段子系统获取）：中型单舱单列 6 位、大型单舱双列 8 位、串列双舱前 3 + 后 4、重载单舱双列 12 位；单货位限重 700 kg。

## 代码结构

```
src/
  algo/            纯 TypeScript 算法（不依赖界面，可在 Node 中运行）
    allocate.ts      多盘分配
    pipeline.ts      分配 → 逐盘码放 → 回流的联动流程
    layout.ts        单盘空间布局（pattern.ts / maxrects.ts / freepack.ts 为其子模块）
    bearing.ts       货物承压：压重自上而下传递
```

## 口径、假设与已知限制

- **货盘可用空间**默认 1200×1200×1500（本项目）；可在"参数"里切换为技术要求表 2-2 / 图 2-1 的 1000×1000×(1000–1200)。货盘本体仍按技术要求取 1219×1219×75。
- **利用率**相对货盘可用区域、逐层计算、顶层不计。
- **重心偏移基准**默认取货盘边长 1219，可切换为可用区域边长。
- **货物的品类、密度、承压上限**是演示用的示例值（承压上限按"顶面允许压强 × 顶面面积"给出）。正式数据由出库清单逐件给出；不给承压上限的货物按不限处理。
- **承压模型**是静力、刚性箱体、按接触面积分配，不考虑运输振动和箱体蠕变；布局阶段留了 5% 余量。
- **起步阶段**取"盘上货物不足整盘货重的 20%"，这几步不计入过程峰值（原因见上文）。这是我方的口径，待确认。
- **机械臂**：作业指令与设备无关；界面里的四轴机械臂、输送线位置、节拍估算都是演示用的示例。真实设备的型号、取料点位置、通信协议、夹具和安全区需要现场确定；指令没有考虑夹具与相邻货物的侧向干涉。
- **支撑率下限 80%**、层间压缝率、过程包线等为研发假设，待确认。
- **舱段构型、空机质量属性、理论重心、包线、货位限重**均为内置示例值，由配置驱动；正式数据以舱段子系统提供的为准。
- 过程重心是准静态分析，不是飞行动力学仿真。
- 演示版的登录在本机校验，数据保存在浏览器本地；正式版对应服务端的认证、数据库与真实接口收发。
- 货物重心假设在几何中心；实测重心通过"实测复核"流程回传后参与装载复核。
