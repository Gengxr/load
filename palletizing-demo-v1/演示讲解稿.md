# 单盘动态码放 Demo · 演示讲解稿（约 11 分钟）

> 使用：Chrome 打开 `单盘动态码放演示.html` → 按 F11 全屏。默认场景为"标准规格 · 种子 20261052"（117 件、6 层），
> 每次打开结果一致。下文 **【操作】** 是要点的按钮，「 」里是可以直接说的话。

---

## 0 开场（30 秒）

「码盘与装载方案规划模块里，第一道工序是把散货码到货盘上。我们今天演示的是其中的**单盘码放规划**：
一个货盘、分到这个货盘上的一批货，算出**每件放哪、按什么顺序放**，并用三维动画引导工人一件一件码。」

**【操作】** 指一下顶部流程条：货物生成 → 多盘分配 → 单盘布局 → 顺序规划 → 动态码放 → 指标验证。
「多盘分配是另一位同学负责的部分，这里预留了接口，可以直接导入它的结果。」

## 1 规划演示（3 分钟）

**【操作】** 点左侧「标准规格」（已默认选中）→ 点底部 ▶ 播放（1×）。

- 「左边是仓储出库的输送线，**货物就是按我们算出的顺序出库的**——这个顺序本身就是方案的一部分，会下发给仓储系统。」
- 「每一件都是抓取、抬升、平移、**竖直放下**。青色的框是它的目标位置。」
- 「中间这个黄色的球是**整托重心（货物 + 货盘）**，货盘面上的绿色方框是技术要求的 ±10% 容差区。
  大家注意看，码放**全过程**重心都稳稳地在中心附近。」（指左下角「系统重心」卡片的雷达和读数）

**【操作】** 速度调到 4×，让它码完（或点 ⏭ 直接看结果）。

- **【操作】** 点右上角的指标胶囊「技术指标 6/6 达标」（或按 **M**），右侧滑出指标面板：
  「表 2-2 的六项指标，软件自动计算、自动判定，全部达标：重心高度、重心偏移、利用率、垛形外边界、垛形误差、生成用时。
  每一项下面的进度条，竖线是技术要求的限值。**生成一垛只要零点几秒**，技术要求是 2 分钟。」
- 面板最下方「分层方案」：点一层 → 三维里高亮；「虚线是下一层轮廓，可以看到上下层是错缝压着的，不容易散垛。」
  讲完再按 **M** 收起面板，把画面还给三维演示。
- **【操作】** 鼠标悬停任意一个箱子：「可以看到它的编号、RFID、重量，**青色高亮的是托住它的那几件**。」

## 2 方案对比（3 分钟）—— 最关键的一页

**【操作】** 顶部切到「方案对比」（默认是「只比顺序」）→ ▶ 播放（2×）。

「左右两边是**同一批货、同一个码放方案**，唯一的区别是**先放哪件、后放哪件**。
左边是对照基线，叫逐层行扫描：一层码满再码下一层，从一个角扫到另一个角，是人工码盘常见的习惯；右边是我们的算法。」

- 指左侧：「逐层行扫描在码第一层的时候，重心就已经偏到容差区外面去了（容差区变红）。」
- 指右侧：「我们的顺序全程在中心附近。」
- 指下方卡片：「过程峰值偏心 **13% 左右 → 1% 左右**，超出容差的步数 **十几步 → 0**。」

**【操作】** 上方切到「整体对比 · 经典算法 DBLF」→ ⏮ 回到开头 → ▶ 播放（4×）。

「逐层行扫描是我们自己定的对照，不是哪项标准。码放顺序和过程重心这件事，目前没有查到公认的行业标准，
所以我们又找了三维装箱领域文献里常用的一个经典算法 DBLF 来比，中文叫'最深、最低、最左'。
这次左边**位置和顺序都是 DBLF 算的**，货物、约束和评分方法跟我们完全一样。」

- 指左侧：「它是为集装箱设计的，从最里面开始一面一面往外码，所以码的过程中重心一直偏在里侧。」
- 指下方卡片：「过程峰值偏心 **22% 对 1%**，有 **78 步**超出容差；最低层利用率 **46% 对 96%**，利用率这一项不达标。」
- 「这不是说 DBLF 不好，它的目标是把箱子装满。这说明码盘要专门处理重心、分层和顺序，直接拿装箱算法来用是不够的。」

「为什么中间过程也要平衡？码盘工位下面就是重心重量测量装置，托盘长时间偏载，
一是人工码放时容易歪倒、滑落，二是测量台和托盘受偏心力矩。**我们不只保证结果好，还保证过程稳**。」

## 3 图 2-1 复现（1.5 分钟）

**【操作】** 右上「算法原理」→「图 2-1 对照」。

「这是技术要求第 9 页图 2-1 给出的 14 种单规格堆码方式。这 14 张图是我们的算法**现场实时算出来的**，
**14 种全部达到图中的件数**，包括这种中心留一个空位的风车式排布。」

**【操作】** 切到「码放顺序规划」页，简单指一下：「每件货物从上往下放，所以下面的必须先放——这是一张依赖图；
我们在所有合法顺序里，用束搜索找全过程最平衡的那一个。」（不必展开公式）

按 Esc 关闭。

## 4 工位引导（1.5 分钟）

**【操作】** 顶部切到「工位引导」。

「这是给码盘工人看的界面，对应技术要求里'在码盘动画的提示下放置，并用输入设备确认'。」

- 「右边大字：第几件、**RFID 末 6 位**、规格、重量、第几层、朝向，下面的俯视图白框就是这件的位置。」
- **【操作】** 按几下**空格**：「工人放好以后踩一下脚踏——脚踏就是一个 USB 键盘，按一下就确认——系统进入下一件。」
- **【操作】** 按 **←**：「放错了可以回退。」按 **E**：「缺件、破损可以一键上报。」
- 「还会统计作业用时和节拍，方便后续分析效率。」

## 5 适应性（1 分钟）

**【操作】** 回到「规划演示」，依次点「多规格混装」「随机尺寸」，再点骰子换几个种子。

「不同的货物组合都能在一秒左右给出方案。随机尺寸是压力测试：货物凑不成平整层时，利用率会下降，
软件**如实报告未达标**，但稳定性和重心照样保证；实在放不下的件会列入人工处理清单，不会硬塞。」

## 6 收尾（30 秒）

「数据接口是 JSON 的，输入货物清单、输出码放方案和出库顺序，可以直接对接多盘分配和仓储系统。
有几个口径需要和您确认——利用率按图 2-1 的 1000×1000 算、重心偏移的基准长度、支撑率阈值——
确认之后我们按正式指标调整。」

## 备问（可能被问到的问题）

| 问题 | 回答要点 |
|---|---|
| 这是 AI / 大模型吗？ | 不是黑箱。是经典的组合优化：动态规划、装箱启发式、束搜索、局部搜索。每一步都能解释"为什么这样放"，结果可复现（同一种子同一结果）。 |
| 能保证 100% 达标吗？ | 支撑、不碰撞、不越界这些**硬约束每个方案都满足**，并由独立的校验器复核、在界面上报告。利用率取决于货物规格：标准规格下 20 个随机场景 19 个达标，随机尺寸下会如实报告。 |
| 货物实际重心和假设不一样怎么办？ | 目前按会议约定取几何中心。我们的方案终态重心偏移通常在 1% 以内，远小于 ±10%，给实际偏差留了很大余量；正式方案里整托码完会实测重量重心（三点多角度称重），实测超限进入返工流程。 |
| 多个货盘、装进货舱怎么办？ | 多盘分配是另一位同学的部分，接口已预留；整托进舱的装载配平是下一阶段，方案文档里已有设计。 |
| 算得慢不慢？ | 一垛 100 件左右约 0.5–1 秒，400 多件的小件约 1.5 秒，技术要求是 2 分钟。算法在后台线程运行，界面不卡。 |
| 对比用的是什么标准？ | 码放顺序和过程重心没有查到公认的标准或公开基准。我们用两个对照：逐层行扫描是自定义基线（同一垛形只换顺序）；DBLF 是文献中常用的经典装箱算法（Karabulut 和 İnceoğlu，2004），按同样的约束和评分方法实现。最终结果是否合格按技术要求表 2-2 判定。 |
| 为什么不一层码完再码下一层？ | 可以设成"严格逐层"（左下「参数」→ 顺序规划）。默认允许在下层局部完成后先码上层来配平，同时控制换层次数，避免工人频繁换层。 |
| 工人看得懂吗？ | 三维动画 + 俯视位置图 + 大字 RFID，便于远处查看；后续会和现场操作员一起迭代界面。 |
